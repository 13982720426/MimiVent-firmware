# MimiVent

ESP32-C3-DevKitM-1 单猫砂盆自动排风固件，包含本地手机网页控制台。当前基础方案使用 **1 个猫砂盆、1 个 PIR、1 台风机**；设备开机后先执行启动冷静期，再进入 PIR 自动感应。手机页面可查看 PIR/风机状态，临时强制开/关均可设定时长，另有需要二次确认的持续关闭锁。三通、第二段支管和第二个 PIR 是连接第二个猫砂盆时才需要的可选扩展，不属于当前基础方案的必需配件。本文档对应首个正式版本 `v0.1.0`，包含准备环境、接线、编译、烧录及功能验证说明。

## 项目启动前准备

### 硬件清单

| 配件 | 本项目使用规格 | 说明 |
| --- | --- | --- |
| 主控板 | ESP32-C3-DevKitM-1 开发板 | 请区分 DevKitM-1 开发板与 C3 SuperMini；引脚布局和板载灯实现可能不同。 |
| PIR 人体红外模块 | 1 个，VCC / OUT / GND | 一个猫砂盆配一个 PIR；当前固件只读取 GPIO4。模块输出应为适配 ESP32 的 3.3V 逻辑电平。 |
| 继电器模块 | 12V 供电、单路、逻辑输入兼容 3.3V | 当前程序按 GPIO5 高电平吸合配置。继电器触点端与线圈/控制端是两组不同接口。 |
| 风机 | 12V DC，约 10W，带 12V 适配器 | 适配器接入 DCP3512 输入；由 DCP3512 的 12V 输出给风机供电。风机额定电流约 0.83A，电源能力还需留启动余量。 |
| DC-DC 电源模块 | DCP3512，12V 输入，提供 3.3V/5V/12V 输出 | 同一模块向 ESP32 提供 3.3V，向风机和继电器提供 12V。接线前按模块丝印确认输入、输出端和调压方式。 |
| 风管（基础方案） | 一段风管及与风机/猫砂盆开口匹配的接口 | 从一个猫砂盆接到风机排风路径；基础方案不需要三通。 |
| 连接材料 | 端子线、杜邦线/端子转接线、绝缘热缩管或电工胶带 | PIR/继电器控制信号可用杜邦线做低压原型；风机电源回路用合适线径和可靠端子，避免用松动的面包板跳线承载风机电流。 |
| 开发连接 | USB 数据线 | 必须支持数据传输；仅充电线无法烧录。 |

购买替代模块时，应核对实际额定电压、风机电流、继电器触发电平和引脚定义，不要只按商品标题判断兼容性。

### 可选：扩展到两个猫砂盆

要让两个猫砂盆分别感应并共用一台风机，可额外准备：

- 第二个 PIR 模块（总计 2 个）；
- 50mm 三通及第二段支管/风管；
- 与第二个 PIR 对应的 GPIO 接线，并修改固件，让任意一个 PIR 触发都能启动风机。

**当前固件还没有启用第二个 PIR**：GPIO3 未接入状态机，页面也只显示 GPIO4 的传感器状态。因此，在完成代码扩展和实测前，不要把“接上第二个 PIR”理解为固件会自动识别。三通和双支路也属于后续风道扩展，当前单盆调试可先不安装。

### 软件与开发环境

- macOS、Windows 或 Linux 均可开发；Arduino IDE 2.x 可用于编辑、编译和烧录。本项目不要求 Windows。
- 需要安装的软件：Arduino IDE 2.x、Espressif Systems 的 `esp32` 板卡包、`Adafruit NeoPixel` 库。
- `WiFi`、`WebServer` 和 `Preferences`（NVS 配置存储）库由 ESP32 Arduino core 自带，不要在 Library Manager 里另外安装同名库。
- 当前已验证的构建组合：Arduino IDE 2.3.10、ESP32 Arduino core `esp32:esp32` 3.3.12、Adafruit NeoPixel 1.15.5。其他版本可能可用；遇到编译差异时，先回到这组版本复现。
- 将本仓库整个项目目录放在 Arduino sketchbook 下，保持目录名和主 `.ino` 文件名一致：`MimiVent/MimiVent.ino`。
- 首次接线烧录时使用 USB 数据线连接开发板；在 IDE 中选择对应串口和 `ESP32C3 Dev Module` 板卡配置。

#### 安装 ESP32 板卡包

1. 安装并打开 Arduino IDE 2.x。
2. 打开 **Arduino IDE → Settings/Preferences（设置/首选项）**，找到 **Additional Boards Manager URLs（附加开发板管理器网址）**。
3. 添加 Espressif 官方稳定版板卡索引：

   ```text
   https://espressif.github.io/arduino-esp32/package_esp32_index.json
   ```

   如果该栏已有其他网址，用逗号分隔或点右侧管理按钮新增一行，不要覆盖原有配置。
4. 打开左侧 **Boards Manager（开发板管理器）**，搜索 `esp32`，安装发布者为 **Espressif Systems** 的 **esp32** 板卡包。安装完成后记下版本号，便于日后复现相同构建环境。

#### 安装 NeoPixel 库

1. 打开左侧 **Library Manager（库管理器）**。
2. 搜索 `Adafruit NeoPixel`。
3. 选择作者为 **Adafruit** 的库并点击 **Install（安装）**。如果 IDE 提示同时安装依赖，按提示一并安装。

#### 选择 C3 开发板和串口

1. 用 USB 数据线连接 ESP32-C3-DevKitM-1。
2. 从 IDE 顶部的开发板选择器中选择 **ESP32C3 Dev Module**。如果列表中没有该选项，先确认 Espressif `esp32` 板卡包已经安装完成。
3. 在 **Tools（工具）** 菜单确认板型为 `ESP32C3 Dev Module`，选择开发板插入后出现的 **Port（端口）**。端口名称因操作系统和 USB 转串口芯片而异；不确定时可拔插开发板，观察哪个端口随之消失/出现。
4. 本项目使用板载默认 4MB Flash。若工具菜单显示 **Flash Size（闪存大小）**，选择 `4MB (32Mb)`；其他选项保持该板型默认值即可。

### 接线前安全检查

1. 先断开 12V 适配器，完成接线后再上电；调试时可先断开继电器 `NO` 到风机正极的导线并绝缘。
2. DCP3512 的输入电压和输出端必须按板上 `IN/OUT`、`+/−` 标记确认；不要根据端子位置猜测。上电前用万用表确认输出电压。
3. ESP32 的 GPIO 只能接 3.3V 逻辑信号。不要把 5V 或 12V 接到 GPIO、PIR OUT 或继电器 IN。
4. 所有控制信号必须有共同参考地：ESP32 GND、PIR GND、继电器控制侧 GND 和 DCP3512 输出 GND 相连。若继电器板有光耦隔离/独立电源端子，应按该板说明确认是否需要共地。
5. 风机正极通过继电器触点切换；风机由 DCP3512 的 12V 输出供电，不能让风机电流流经 ESP32、杜邦线、面包板或 DCP3512 的 3.3V/5V 输出。
6. 裸露的 12V 端子应做好绝缘和固定；不要在带电状态下插拔松散导线。

## 接线说明

下表对应当前基础方案：**一个猫砂盆、一个 PIR、ESP32-C3-DevKitM-1、12V 单路继电器和 12V 风机**。不包含三通或第二个 PIR。上电前请以每块实物的丝印及说明书复核端子名称。

### 低压控制侧

| 起点 | 接到 | 用途 |
| --- | --- | --- |
| 12V 适配器正极 | DCP3512 输入 `IN+` | 为电源模块供电；连接前按实际板卡丝印确认输入端。 |
| 12V 适配器负极 | DCP3512 输入 `IN-` | 电源模块输入回路负极。若适配器自带 DC 插头，使用匹配的 DC005 转接线并先确认极性。 |
| DCP3512 `3.3V+` | ESP32 `3V3` | 给 ESP32-C3 开发板供电。调试时也可改用 USB 单独供电；不要同时连接未经确认的多个供电源。 |
| DCP3512 `GND` | ESP32 `GND` | 控制侧公共地，也连接 PIR 和继电器控制侧地。 |
| PIR `VCC` | 3.3V 电源 | PIR 供电。若具体 PIR 模块要求 5V，需确认其 OUT 高电平仍不超过 ESP32 GPIO 的 3.3V 上限；不确定时先查模块资料/测量。 |
| PIR `GND` | 公共 `GND` | PIR 地。 |
| PIR `OUT` | ESP32 `GPIO4` | 当前唯一启用的感应输入。 |
| 继电器模块 `DC+` | DCP3512 `12V+` | 给 12V 继电器模块供电。 |
| 继电器模块 `DC-` | DCP3512 `GND` | 继电器控制侧回路地。 |
| 继电器 `IN` | ESP32 `GPIO5` | ESP32 控制继电器；当前代码配置为高电平吸合。 |

> 若继电器板的 `DC-/GND`、`IN` 标注或供电方式与上表不同，请先查看该继电器板说明，不要把继电器触点的 `COM/NO/NC` 当作线圈供电端。

### 风机 12V 触点回路

```text
DCP3512 输入 IN+ / IN- ◀── 12V 适配器正极 / 负极
DCP3512 12V+ ────────────┬── 继电器模块 DC+
                         └── 继电器 COM
继电器 NO ───────────────── 风机正极
风机负极 ────────────────── DCP3512 GND
继电器模块 DC- ───────────── DCP3512 GND
继电器 NC ─────────── 悬空并单独绝缘
DCP3512 3.3V+ ───────────── ESP32 3V3
DCP3512 GND ─────────────── ESP32 GND、PIR GND
```

12V 适配器是整套系统的输入电源。DCP3512 将输入分配为 3.3V 和 12V：3.3V 给 ESP32，12V 给继电器模块和风机。风机正极经过继电器 `COM-NO`，负极回到 DCP3512 `GND`。继电器未吸合时 `COM-NO` 断开、风机停止；继电器吸合后触点闭合、风机运行。确认 DCP3512 的 12V 输出持续电流和启动余量能满足风机与继电器的总负载。

风机原装 12V 适配器的 DC 插头通过匹配的 DC005 转接线接到 DCP3512 输入；先核对适配器正负极和模块输入丝印，不要把适配器直接接到模块输出端。所有接线和改线都应在断电状态下进行。

### 可选双盆风道示意（仅硬件扩展参考）

```text
猫砂盆 A ── 支管 A ──┐
                      ├── 50mm 三通 ── 风机进气端 ── 排风出口
猫砂盆 B ── 支管 B ──┘
```

该示意只说明风管分支关系，不代表当前固件已支持双 PIR。扩展前还需确认三通方向、接口密封、风机进/出风方向及两条支管的实际吸力。

### 引脚汇总

| ESP32-C3 引脚 | 当前用途 | 备注 |
| --- | --- | --- |
| GPIO4 | PIR OUT | 单 PIR 输入，HIGH 表示检测到活动。 |
| GPIO5 | 继电器 IN | 高电平吸合；若实物继电器为低电平触发，应修改 `AppConfig.h` 中的 `kRelayActiveLow` 并重新实测。 |
| GPIO8 | 板载 WS2812 状态灯 | 代码使用 Adafruit NeoPixel 驱动。 |
| GPIO3 | 未使用 | 预留给未来第二个 PIR；当前不接入、不参与控制。 |
| 3V3 / GND | 控制侧供电与公共地 | 不要将 12V 接入这些引脚。 |

## 从零编译与烧录

1. 按照“软件与开发环境”一节安装 Arduino IDE、Espressif `esp32` 板卡包和 Adafruit `Adafruit NeoPixel` 库。
2. 在 Finder/文件管理器中打开项目目录，并用 Arduino IDE 打开 `MimiVent.ino`。确认主 `.ino` 文件仍位于同名 `MimiVent` 文件夹内。
3. 连接开发板，选择 `ESP32C3 Dev Module` 和对应 USB 串口。
4. 点击左上角 **Verify（验证/编译，勾号）**。首次编译会下载/准备 ESP32 构建工具，可能比后续编译花更久；等待输出区出现编译成功信息。
5. 编译成功后点击 **Upload（上传，右箭头）**。上传失败且提示连接超时时，按住板上的 `BOOT`，点击上传，在 IDE 开始连接/写入时松开；不同开发板的进入下载模式操作可能略有差异。
6. 上传完成后打开 **Serial Monitor（串口监视器）**，将波特率设为 `115200`，按一次 `RST`。启动日志应包含固件版本、AP 名称、控制地址和时序模式。
7. 手机连接 `MimiVent`（密码 `MimiVent`），浏览器访问 `http://192.168.4.1`，测试自动感应和定时按钮。

也可使用 Arduino CLI 编译：

```sh
arduino-cli compile --fqbn esp32:esp32:esp32c3 MimiVent
```

如使用 CLI，需先安装对应 ESP32 core 和 `Adafruit NeoPixel` 库；串口上传需要把命令中的 FQBN、串口名替换为本机实际值。

## 首次上电与验证

1. 首次烧录/网页联调时先断开风机正极并绝缘，确认 ESP32、PIR、继电器控制端供电正确。
2. 上电后观察串口启动日志和板载灯；确认手机能连接 AP 并打开控制页面。
3. 对当前唯一的猫砂盆和 PIR 测试触发：状态灯切换到橙黄色运行效果、继电器吸合、页面显示风机运行；PIR 回到 LOW 后按配置延时停止。
4. 测试网页的定时排风、临时暂停和持续关闭，再确认到期后恢复自动感应；状态卡片和所选模式应与实际风机状态一致。
5. 控制逻辑确认后断电，再接回风机正极并固定、绝缘所有端子；重新上电验证风机动作。

本项目的实际联调已验证：**单猫砂盆、单 PIR** 自动感应、网页强制排风、临时暂停及定时到期恢复均可工作。双盆风道和第二个 PIR 尚属于后续扩展，不包含在当前验证范围内。修改固件后仍应重新烧录并按上述步骤检查。

## 当前硬件与已验证逻辑

- PIR OUT：GPIO4；继电器 IN：GPIO5；板载 WS2812：GPIO8。
- 继电器使用高电平触发（`kRelayActiveLow = false`）；12V 适配器接 DCP3512 输入，DCP3512 的 12V 输出经继电器 `COM-NO` 控制风机正极，风机负极回 DCP3512 GND；DCP3512 的 3.3V 输出给 ESP32。
- 待机蓝色呼吸灯、风机关闭；PIR 触发后橙色快速呼吸灯、风机开启；PIR LOW 后延时关闭。
- 当前基础方案是一个猫砂盆、一个 PIR 和一台风机；第二个 PIR 暂不接入，GPIO3 目前不参与程序。三通及第二条支管是双盆扩展选项。

## 手机网页控制台

本版使用 ESP32 自建 Wi-Fi 热点（AP），不依赖路由器和外网，也没有额外网页库依赖。页眉 Logo 以内嵌 data URI 显示，标签图标通过 `/favicon.png` 提供，图标数据保存在 `FaviconAsset.h`。

1. Arduino IDE 选择 `ESP32C3 Dev Module`，Flash Size 设为 `4MB (32Mb)`，Partition Scheme 设为 `Default 4MB with spiffs`。
2. 上传项目目录中的 `MimiVent.ino`。
3. 手机连接 Wi-Fi：`MimiVent`，密码：`MimiVent`。
4. 浏览器访问 `http://192.168.4.1`。

连接 ESP32 自建热点期间，手机通常无法同时通过该 Wi-Fi 上网；这是 AP 模式的正常表现。当前页面和设备状态只在手机与 ESP32 的本地连接中可用，不提供云端远程访问。

控制页面由 `/` 正式运行页和 `/dev` 联调页共用同一套响应式布局。顶部以纯文本显示设备本地地址 `192.168.4.1`；正式页和 DEV 页使用同一个设备 IP，DEV 页通过 `/dev` 路径访问。底部显示当前正式/DEV 配置及切换入口。设备重启后默认使用正式配置；如果浏览器仍停留在 DEV 页，页面会提示页面配置与设备配置不一致，并锁定所有控制及时间设置。此时可确认切换设备到当前页面配置，或直接打开设备当前配置对应的页面。设备端控制和配置写入 API 也会拒绝不匹配页面的请求。切换配置前会弹窗确认；确认后立即停止风机、取消当前排风或暂停任务，并以目标配置的时序重新进入自动感应。页面每秒刷新设备状态、PIR 电平、风机运行时长和当前阶段倒计时，不依赖外部 CDN。

状态卡片同时展示设备当前实际使用环境的五项时序配置，并在启动冷静期、自动离开确认、自动排风、临时排风、临时暂停或强制测试时突出显示本次阶段/操作使用的时长与说明。保存新配置不会改写已开始任务的计时；运行卡片显示该任务启动时实际采用的时长。

自动感应遵循 PIR 优先停风流程：PIR HIGH 时立即停止风机并等待；PIR 连续 LOW 达到离开确认时间后，启动一轮自动排风；自动排风到时停止并等待下一次活动。排风期间再次检测到 HIGH 会立即停风、清除本轮计时，之后重新确认离开并完整排风一轮。

首页提供自动感应、立即临时排风、临时暂停、强制排风测试和持续关闭。临时排风遵守 PIR 优先；强制排风测试是单独的限时操作，会明确忽略 PIR。暂停到期后先重新进入自动流程。持续关闭需要二次确认，保持至用户手动恢复自动感应或设备重启。一次只运行一个定时任务；切换任务时先确认取消当前任务，不排队、不保留旧倒计时。重复点击同一个运行中的任务不会重置时间。

时间设置收纳在可展开区域，正式和 DEV 配置独立保存。五项配置为启动冷静期、离开确认、自动排风、临时排风和临时暂停时长。它们共用同一个滚轮选择器和预设值：0、5、10、20、30 秒、1、2、3、5、10 分钟。0 秒只允许用于离开确认。设置显式保存到 ESP32 NVS；修改参数不改变已经开始的倒计时。设置区提供“重置配置”，二次确认后只恢复当前页面环境的默认值。

手机端滚轮从底部弹出，选中值对齐中间高亮行；桌面端使用居中选择面板。页面顶部突出显示设备运行状态和所处阶段，静态信息卡片与可操作按钮采用不同视觉样式；持续关闭按钮使用红色危险样式。底部显示热点名称和密码。

热点名和密码在 `AppConfig.h` 的 `kApSsid`、`kApPassword` 修改。网页底部从固件配置接口读取并显示这两个值；修改配置后重新编译、烧录即可同步更新。ESP32 SoftAP 密码必须至少 8 个字符。

`v0.1.0` 已在 ESP32-C3-DevKitM-1 上完成实机功能验证，包括单 PIR 自动排风、本地网页控制、定时排风与暂停、持续关闭、时序配置和环境切换。双盆风道及第二个 PIR 尚未纳入固件验证范围。

## 时序配置

时间设置通过网页调整并保存在 ESP32 NVS 中，无需为更改时序重新编译或烧录。首次运行默认值如下：

| 配置项 | 正式运行 `/` | DEV 联调 `/dev` |
| --- | ---: | ---: |
| 启动冷静期 | 30 秒 | 5 秒 |
| 离开确认时间 | 30 秒 | 0 秒 |
| 自动排风时长 | 2 分钟 | 10 秒 |
| 临时排风时长 | 1 分钟 | 10 秒 |
| 临时暂停时长 | 5 分钟 | 10 秒 |

每项都可选择 0、5、10、20、30 秒或 1、2、3、5、10 分钟；只有离开确认时间支持 0。两套配置分别保存，改动后点击“保存设置”。“重置配置”会将当前环境五项时序恢复为表中默认值并立即保存。保存或重置不会重置正在进行的计时，从下一轮或下一次手动操作起使用新值。升级时会把旧固件内置的正式 1 分钟和 DEV 10 秒冷静期默认值迁移到新默认值；其他已自定义时长保留。

设备上电或烧录后重启时，先进入启动冷静期并保持风机关闭，同时监测 PIR 电平但不执行自动排风。冷静期默认正式 30 秒、DEV 5 秒；普通临时排风和临时暂停在冷静期内不可启动。强制排风测试与持续关闭可以跳过冷静期：测试会取消剩余冷静期并按所选时长运行，结束后回到自动感应；持续关闭会取消冷静期并保持关闭，直到手动恢复自动感应。每次重启都默认进入正式配置；DEV 仅在本次开机期间有效。两套时序参数分别保存在 NVS，切换环境后按目标环境的冷静期重新计时。若浏览器仍停留在 `/dev`，页面会提示配置不一致并锁定操作，直到用户确认切换设备或打开正式页。

PIR 模块自身输出 HIGH 的保持时间由模块电位器控制；软件离开确认时间从模块输出转为 LOW 后才开始计算。因此两者会共同决定猫离开后的实际等待时间。

## 建议的网页联调顺序

1. 第一次验证网页时，让风机 12V 正极保持断开并做好绝缘，给 ESP32、PIR 和继电器控制侧供电。
2. 手机连接 `MimiVent` 并打开 `http://192.168.4.1`，检查页面能显示在线、PIR 状态和模式。
3. 测试一个短时排风和短时暂停选项，确认倒计时结束后自动恢复感应；再测试持续关闭按钮的二次确认和“立即恢复自动感应”。
4. 断电后再接回风机正极，重新上电测试自动排风和延时停止。

## 固件模块

主程序 `MimiVent.ino` 只负责初始化各模块和执行非阻塞循环调度。各文件职责如下：

- `AppConfig.h`：引脚、继电器有效电平、PIR 轮询间隔及热点配置。
- `SettingsStore.h/.cpp`：正式/DEV 两套时序默认值、选项校验和 NVS 持久化。
- `FanController.h/.cpp`：PIR 优先停风、离开确认、自动排风和限时控制状态机。
- `WifiManager.h/.cpp`：ESP32 SoftAP 初始化及本地 IP 查询。
- `WebDashboard.h/.cpp`：正式/DEV 页面、公共滚轮选择器、状态 JSON 和控制 API。
- `StatusLed.h/.cpp`：板载 WS2812 状态灯效果。
- `FirmwareVersion.h`：固件语义化版本号。

模块间通过头文件中的接口协作。修改状态机时优先在 `FanController` 内实现；页面只提交控制命令并展示状态，避免把风机逻辑放进网页处理器。关键状态转换和硬件约束在相应模块及接口处有中文注释。

## 版本管理

- 当前正式版本：`v0.1.0`。此前提交均为未纳入版本号管理的硬件和网页调试 demo。
- 版本号集中在 `FirmwareVersion.h`，页面和串口启动日志自动读取该版本。
- 每次迭代在 `CHANGELOG.md` 记录功能变化；准备发布时同步更新版本号并创建 Git tag，例如 `v0.2.0`。
- 使用 `MAJOR.MINOR.PATCH`：不兼容改动升 MAJOR；新增兼容功能升 MINOR；兼容性修复升 PATCH。

## 编译

本机验证命令：

```sh
arduino-cli compile --fqbn esp32:esp32:esp32c3 MimiVent
```

依赖：ESP32 Arduino core 自带的 `WiFi`、`WebServer`，以及项目已有的 `Adafruit NeoPixel` 库。

本项目用 `.clang-format` 固定 Arduino C++ 的格式风格（Google C++ 基础、2 空格缩进、100 列）。格式化时只处理 `.ino/.h/.cpp`，不要对 `WebDashboard.cpp` 内的 HTML 原始字符串做重写。当前每次修改至少执行 Arduino 编译；页面脚本修改后再用 `node --check` 检查脚本语法，并用 `git diff --check` 检查空白错误。涉及风机模式或计时逻辑时，再补状态转换测试或实机验证。若系统未安装 `clang-format`，格式化检查需先安装对应工具；仅编译通过不代表格式检查已通过。
