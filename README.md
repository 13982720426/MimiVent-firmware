# MimiVent

ESP32-C3-DevKitM-1 单猫砂盆自动排风固件，通过 MimiVent App 的 BLE 或 WiFi 控制设备。当前基础方案使用 **1 个猫砂盆、1 个 PIR、1 台风机**；设备开机后先执行启动冷静期，再进入 PIR 自动感应。手机页面可查看 PIR/风机状态，临时强制开/关均可设定时长，另有需要二次确认的持续关闭锁。三通、第二段支管和第二个 PIR 是连接第二个猫砂盆时才需要的可选扩展，不属于当前基础方案的必需配件。当前固件版本为 `v0.6.0`，配套 App `v0.6.0`；上一正式固件为 `v0.5.1`。WiFi 配网与 HTTPS 控制已完成用户真机验证。变化见 [CHANGELOG.md](CHANGELOG.md)。

## 项目启动前准备

### 硬件清单

| 配件 | 本项目使用规格 | 说明 |
| --- | --- | --- |
| 主控板 | ESP32-C3-DevKitM-1 开发板 | 请区分 DevKitM-1 开发板与 C3 SuperMini；引脚布局和板载灯实现可能不同。 |
| PIR 人体红外模块 | 1 个，VCC / OUT / GND | 一个猫砂盆配一个 PIR；当前固件只读取 GPIO4。模块输出应为适配 ESP32 的 3.3V 逻辑电平。 |
| 继电器模块 | 12V 供电、单路、逻辑输入兼容 3.3V | 当前程序按 GPIO5 高电平吸合配置。继电器触点端与线圈/控制端是两组不同接口。 |
| 风机 | 12V DC，约 10W，带 12V 适配器 | 适配器接入 DCP3512 输入；由 DCP3512 的 12V 输出给风机供电。风机额定电流约 0.83A，电源能力还需留启动余量。 |
| DC-DC 电源模块 | DCP3512，12V 输入，提供 3.3V/5V/12V 输出 | 同一模块向 ESP32 提供 3.3V，向风机和继电器提供 12V。接线前按模块丝印确认输入、输出端和调压方式。 |
| 风管（基础方案） | 一段风管及与风机/猫砂盆开口匹配的接口 | 从一个猫砂盆接到风机排风路径；基础方案不需要三通。 |
| 连接材料 | 端子线、杜邦线/端子转接线、绝缘热缩管或电工胶带 | PIR/继电器控制信号可用杜邦线做低压原型；风机电源回路用合适线径和可靠端子，避免用松动的面包板跳线承载风机电流。 |
| 开发连接 | USB 数据线 | 必须支持数据传输；仅充电线无法烧录。 |

购买替代模块时，应核对实际额定电压、风机电流、继电器触发电平和引脚定义，不要只按商品标题判断兼容性。

### 可选：扩展到两个猫砂盆

要让两个猫砂盆分别感应并共用一台风机，可额外准备：

- 第二个 PIR 模块（总计 2 个）；
- 50mm 三通及第二段支管/风管；
- 与第二个 PIR 对应的 GPIO 接线，并修改固件，让任意一个 PIR 触发都能启动风机。

**当前固件还没有启用第二个 PIR**：GPIO3 未接入状态机，页面也只显示 GPIO4 的传感器状态。因此，在完成代码扩展和实测前，不要把“接上第二个 PIR”理解为固件会自动识别。三通和双支路也属于后续风道扩展，当前单盆调试可先不安装。

### 软件与开发环境

- macOS、Windows 或 Linux 均可开发；Arduino IDE 2.x 可用于编辑、编译和烧录。本项目不要求 Windows。
- 需要安装的软件：Arduino IDE 2.x、Espressif Systems 的 `esp32` 板卡包、`Adafruit NeoPixel` 库、`NimBLE-Arduino` 库。
- `WiFi`、ESP-IDF HTTPS/TLS 和 `Preferences`（NVS 配置存储）库由 ESP32 Arduino core 自带，不要在 Library Manager 里另外安装同名库。
- 当前构建组合：Arduino IDE 2.3.10、ESP32 Arduino core `esp32:esp32` 3.3.12、Adafruit NeoPixel 1.15.5、NimBLE-Arduino 2.5.1。v0.4.0 已通过 Arduino CLI 编译及 USB 烧录校验，并完成 BLE OTA 完整包/差分包、暂停续传、安装重连核验和任务放弃/替换真机验证；v0.5.0 为 WiFi 功能版本；v0.5.1 将 WiFi 绑定上限提升到 3 个；v0.6.0 统计存储升到 schema 7（事件容量 512 → 256）并将 WiFi 响应改为短键，需与 App v0.6.0 配套。应用槽上限为 1,769,472 字节。
- 将本仓库整个项目目录放在 Arduino sketchbook 下，保持目录名和主 `.ino` 文件名一致：`MimiVent/MimiVent.ino`。
- 首次接线烧录时使用 USB 数据线连接开发板；在 IDE 中选择对应串口和 `ESP32C3 Dev Module` 板卡配置。

#### 安装 ESP32 板卡包

1. 安装并打开 Arduino IDE 2.x。
2. 打开 **Arduino IDE → Settings/Preferences（设置/首选项）**，找到 **Additional Boards Manager URLs（附加开发板管理器网址）**。
3. 添加 Espressif 官方稳定版板卡索引：

   ```text
   https://espressif.github.io/arduino-esp32/package_esp32_index.json
   ```

   如果该栏已有其他网址，用逗号分隔或点右侧管理按钮新增一行，不要覆盖原有配置。
4. 打开左侧 **Boards Manager（开发板管理器）**，搜索 `esp32`，安装发布者为 **Espressif Systems** 的 **esp32** 板卡包。安装完成后记下版本号，便于日后复现相同构建环境。

#### 安装 NeoPixel 库

1. 打开左侧 **Library Manager（库管理器）**。
2. 搜索 `Adafruit NeoPixel`。
3. 选择作者为 **Adafruit** 的库并点击 **Install（安装）**。如果 IDE 提示同时安装依赖，按提示一并安装。

#### 安装 NimBLE-Arduino 库

1. 打开 **Library Manager（库管理器）**。
2. 搜索 `NimBLE-Arduino`，选择作者为 **h2zero** 的库并安装 `2.5.1`。
3. 本项目使用 BLE-only 的 NimBLE 栈；不要另外安装/引用 ESP32 core 自带的 `BLE`（Bluedroid）库。

#### 选择 C3 开发板和串口

1. 用 USB 数据线连接 ESP32-C3-DevKitM-1。
2. 从 IDE 顶部的开发板选择器中选择 **ESP32C3 Dev Module**。如果列表中没有该选项，先确认 Espressif `esp32` 板卡包已经安装完成。
3. 在 **Tools（工具）** 菜单确认板型为 `ESP32C3 Dev Module`，选择开发板插入后出现的 **Port（端口）**。端口名称因操作系统和 USB 转串口芯片而异；不确定时可拔插开发板，观察哪个端口随之消失/出现。
4. 本项目使用板载 4MB Flash。当前版本使用根目录的 `partitions.csv`，包含双 OTA 应用槽和 512 KiB 统计分区；不要改用旧版 `Minimal SPIFFS` 或默认分区。完整 WiFi 版本还依赖项目隔离的 TLS 4 KiB SDK 副本，推荐使用下方构建脚本；IDE 默认编译不会自动启用本版 WiFi 构建参数。若工具菜单显示 **Flash Size（闪存大小）**，选择 `4MB (32Mb)`。

### 接线前安全检查

1. 先断开 12V 适配器，完成接线后再上电；调试时可先断开继电器 `NO` 到风机正极的导线并绝缘。
2. DCP3512 的输入电压和输出端必须按板上 `IN/OUT`、`+/−` 标记确认；不要根据端子位置猜测。上电前用万用表确认输出电压。
3. ESP32 的 GPIO 只能接 3.3V 逻辑信号。不要把 5V 或 12V 接到 GPIO、PIR OUT 或继电器 IN。
4. 所有控制信号必须有共同参考地：ESP32 GND、PIR GND、继电器控制侧 GND 和 DCP3512 输出 GND 相连。若继电器板有光耦隔离/独立电源端子，应按该板说明确认是否需要共地。
5. 风机正极通过继电器触点切换；风机由 DCP3512 的 12V 输出供电，不能让风机电流流经 ESP32、杜邦线、面包板或 DCP3512 的 3.3V/5V 输出。
6. 裸露的 12V 端子应做好绝缘和固定；不要在带电状态下插拔松散导线。

## 接线说明

下表对应当前基础方案：**一个猫砂盆、一个 PIR、ESP32-C3-DevKitM-1、12V 单路继电器和 12V 风机**。不包含三通或第二个 PIR。上电前请以每块实物的丝印及说明书复核端子名称。

### 低压控制侧

| 起点 | 接到 | 用途 |
| --- | --- | --- |
| 12V 适配器正极 | DCP3512 输入 `IN+` | 为电源模块供电；连接前按实际板卡丝印确认输入端。 |
| 12V 适配器负极 | DCP3512 输入 `IN-` | 电源模块输入回路负极。若适配器自带 DC 插头，使用匹配的 DC005 转接线并先确认极性。 |
| DCP3512 `3.3V+` | ESP32 `3V3` | 给 ESP32-C3 开发板供电。调试时也可改用 USB 单独供电；不要同时连接未经确认的多个供电源。 |
| DCP3512 `GND` | ESP32 `GND` | 控制侧公共地，也连接 PIR 和继电器控制侧地。 |
| PIR `VCC` | 3.3V 电源 | PIR 供电。若具体 PIR 模块要求 5V，需确认其 OUT 高电平仍不超过 ESP32 GPIO 的 3.3V 上限；不确定时先查模块资料/测量。 |
| PIR `GND` | 公共 `GND` | PIR 地。 |
| PIR `OUT` | ESP32 `GPIO4` | 当前唯一启用的感应输入。 |
| 继电器模块 `DC+` | DCP3512 `12V+` | 给 12V 继电器模块供电。 |
| 继电器模块 `DC-` | DCP3512 `GND` | 继电器控制侧回路地。 |
| 继电器 `IN` | ESP32 `GPIO5` | ESP32 控制继电器；当前代码配置为高电平吸合。 |

> 若继电器板的 `DC-/GND`、`IN` 标注或供电方式与上表不同，请先查看该继电器板说明，不要把继电器触点的 `COM/NO/NC` 当作线圈供电端。

### 风机 12V 触点回路

```text
DCP3512 输入 IN+ / IN- ◀── 12V 适配器正极 / 负极
DCP3512 12V+ ────────────┬── 继电器模块 DC+
                         └── 继电器 COM
继电器 NO ───────────────── 风机正极
风机负极 ────────────────── DCP3512 GND
继电器模块 DC- ───────────── DCP3512 GND
继电器 NC ─────────── 悬空并单独绝缘
DCP3512 3.3V+ ───────────── ESP32 3V3
DCP3512 GND ─────────────── ESP32 GND、PIR GND
```

12V 适配器是整套系统的输入电源。DCP3512 将输入分配为 3.3V 和 12V：3.3V 给 ESP32，12V 给继电器模块和风机。风机正极经过继电器 `COM-NO`，负极回到 DCP3512 `GND`。继电器未吸合时 `COM-NO` 断开、风机停止；继电器吸合后触点闭合、风机运行。确认 DCP3512 的 12V 输出持续电流和启动余量能满足风机与继电器的总负载。

风机原装 12V 适配器的 DC 插头通过匹配的 DC005 转接线接到 DCP3512 输入；先核对适配器正负极和模块输入丝印，不要把适配器直接接到模块输出端。所有接线和改线都应在断电状态下进行。

### 可选双盆风道示意（仅硬件扩展参考）

```text
猫砂盆 A ── 支管 A ──┐
                      ├── 50mm 三通 ── 风机进气端 ── 排风出口
猫砂盆 B ── 支管 B ──┘
```

该示意只说明风管分支关系，不代表当前固件已支持双 PIR。扩展前还需确认三通方向、接口密封、风机进/出风方向及两条支管的实际吸力。

### 引脚汇总

| ESP32-C3 引脚 | 当前用途 | 备注 |
| --- | --- | --- |
| GPIO4 | PIR OUT | 单 PIR 输入，HIGH 表示检测到活动。 |
| GPIO5 | 继电器 IN | 高电平吸合；若实物继电器为低电平触发，应修改 `AppConfig.h` 中的 `kRelayActiveLow` 并重新实测。 |

## 编译与 USB 烧录

依赖 ESP32 Arduino core `3.3.12`、Adafruit NeoPixel `1.15.5`、NimBLE-Arduino `2.5.1`。根目录 `partitions.csv` 为实际分区依据：两个各 `0x1B0000`（1,769,472 字节）的 OTA 应用槽和 `0x80000`（512 KiB）统计分区。菜单中的 `huge_app` 只用于构建配置，不代表改用其默认无 OTA 分区表。

完整 WiFi 控制构建使用项目脚本的 **`read4k`** 模式。名称沿用早期阶段命名，当前已包含 WiFi 写控制和统计，不能据此理解为只读。脚本默认 `off`；直接使用默认 Arduino 编译不会启用完整 WiFi 功能。

```sh
bash scripts/build_firmware.sh read4k
```

输出为 `build/firmware-wifi-read4k/MimiVent.ino.bin`，脚本输出实际字节数及 SHA-256。必须确认镜像不超过 1,769,472 字节，并检查构建目录中的 `partitions.csv` 与仓库一致。

此模式启用 `MIMIVENT_ENABLE_WIFI=1`、`MIMIVENT_WIFI_READ_CONTROL=1` 和动态 OTA 工作区，并使用 `build/sdk-tls-4096` 中的隔离 SDK。该目录不入库，新环境必须先准备：

1. 取得脚本锁定的 mbedTLS 官方源码归档 `9d669eadb1955d348986b9280156710aaaadf79f`，存为 `build/mbedtls-9d669ead.tar.gz` 并解压为 `build/mbedtls-9d669eadb1955d348986b9280156710aaaadf79f`。
2. 指定本机 ESP32-C3 SDK 与工具链目录，生成副本；脚本核对源码 SHA-256、SDK 版本和头文件，不修改全局 SDK。锁定 ESP-IDF `v5.5.5 b774170ff46`，不可混用其他 core 的库。

```sh
python3 scripts/build_tls_sdk_overlay.py \
  --sdk /path/to/esp32c3-sdk \
  --toolchain /path/to/riscv32-esp-elf-toolchain \
  --content-bytes 4096
bash scripts/build_firmware.sh read4k
```

`--toolchain` 指向直接包含 `riscv32-esp-elf-gcc` 的 `bin` 目录。具体校验与源码归档哈希以脚本为准；缺失副本或校验不符会停止构建，不能用其他模式冒充完整 WiFi 版本。

连接开发板，选择实际串口后上传同一构建：

```sh
arduino-cli upload \
  --fqbn esp32:esp32:esp32c3:PartitionScheme=huge_app,CDCOnBoot=cdc \
  --port /dev/cu.usbmodemXXXX \
  --input-dir build/firmware-wifi-read4k --verify MimiVent.ino
```

首次从旧分区布局迁移需经 USB 写入正确分区表；正常 OTA 不改分区表。不执行整片擦除，也不随意格式化统计分区。重启后检查串口版本、实际分区和下一 OTA 槽，随后验证 App 状态、控制、统计及网络恢复。

仅 BLE 基线可用 `bash scripts/build_firmware.sh off` 编译。`on` 只启用配网，不等同完整 HTTPS 控制；`probe*`、`identity4k`、`pairprobe4k` 是诊断模式，不作为发布包。

## BLE OTA 升级与签名

App 菜单“固件升级”选择签名 `.mvota` 完整包，或基线镜像匹配的 `.mvdelta` 差分包；不直接上传原始 `.bin`。流程为选择 → 上传/续传 → 完整校验 → 用户确认安装 → 设备重启 → 重连核验版本与镜像身份，上传 100% 不代表最终完成。

新镜像写入非运行 OTA 槽，分块 CRC 与整镜像 SHA-256 校验后验证 RSA-3072/PSS/SHA-256 发布者签名。未验证镜像不得切换启动槽。支持暂停、断连续传、任务查询/放弃/替换，安装提交后不能取消；允许兼容范围内受控降级，仍检查签名、目标芯片、分区与固件身份。

升级、校验、安装期间停风并暂停普通业务；暂停、失败或等待用户安装时退出升级占用、恢复自动控制。实际回滚能力取决于对应构建的 bootloader 回滚配置及首次启动确认。

签名私钥保留在仓库外，不放入 App 或设备。打包与密钥管理见 [固件签名](docs/ota-signing.md)。当前未启用硬件 Secure Boot，无线签名验证不等于防止物理改写 Flash。

日常代码修改至少运行相应原生测试、目标模式 Arduino 构建及 `git diff --check`；涉及状态机/协议时补对应真机回归。仅改说明文档不需要重新刷机。

## 统计数据与同步

- BLE 与 WiFi 共用 `ControlApi` 及统计存储。App 经 BLE 连接后校准手机 Unix 时间和 UTC 偏移；首次可信校时后固定统计时区，按本地自然日查询。
- 采用 schema 4、512 条事件上限和 SPIFFS 双槽快照；每日汇总保留 30 天，明细最多 10 天，亦受事件容量限制。事件淘汰后运行汇总仍可能存在，不能据此判定数据丢失或统计矛盾。
- 运行汇总按小时累计，包含自动、临时、强制排风和当前运行；风机运行期间不每秒写 Flash，结束时保存最终时长。重启未完成运行标记为中断。
- 未校时事件可在本次开机首次校时后回填；在校时前再次断电，无法还原可靠自然日。已初始化分区挂载失败时禁用统计并保留现场，不自动格式化历史数据。
- `GET /api/stats?mode=today|yesterday|threeDays|sevenDays` 返回汇总和图表；`GET /api/events` 支持时间范围、类型筛选和事件 ID 游标分页。`toiletAverageSeconds` 和 `toiletSampleCount` 由全部有效自动排风样本汇总，App 不依赖最近 32 条事件计算平均值。App 负责活动分组与展示。
- `toiletCount` 按当前保留的自动排风记录估算：实际运行达到该次设定时长一半时计入，手动及强制排风不计入；新记录保存启动时设定，旧记录缺失时使用当前正式配置。它不是独立永久日计数，也不是实际人数测量，明细淘汰会影响可追溯范围。
- 统计数据集由 `deviceId`、`dataEpoch`、`bootId` 标识。schema 4 的正常同格式升级不主动清空数据；更早不兼容格式的迁移行为应单独核对，不承诺任意历史格式无损升级。

## 首次上电与验证

1. 首次 USB 烧录或接线联调时先断开风机正极并绝缘，确认 ESP32、PIR、继电器控制端供电正确。
2. 上电后观察串口启动日志和板载灯；在 MimiVent App 中扫描并通过 BLE 连接设备。
3. 对当前唯一的猫砂盆和 PIR 测试触发：状态灯切换到橙黄色运行效果，继电器吸合，App 显示风机运行；PIR 回到 LOW 后按配置延时停止。
4. 在 App 中测试定时排风、临时暂停和持续关闭，再确认到期后恢复自动感应；页面状态和所选模式应与实际风机状态一致。
5. 控制逻辑确认后断电，再接回风机正极并固定、绝缘所有端子；重新上电验证风机动作。

真机已验证 **单猫砂盆、单 PIR** 自动感应、App 蓝牙控制、完整/差分 BLE OTA、暂停续传、重连核验及任务放弃/替换。网页控制现已移除；双盆风道和第二个 PIR 属于后续扩展。

## 当前硬件与已验证逻辑

- PIR OUT：GPIO4；继电器 IN：GPIO5；板载 WS2812：GPIO8。
- 继电器使用高电平触发（`kRelayActiveLow = false`）；12V 适配器接 DCP3512 输入，DCP3512 的 12V 输出经继电器 `COM-NO` 控制风机正极，风机负极回 DCP3512 GND；DCP3512 的 3.3V 输出给 ESP32。
- 待机蓝色呼吸灯、风机关闭；PIR 触发后橙色快速呼吸灯、风机开启；PIR LOW 后延时关闭。
- 当前基础方案是一个猫砂盆、一个 PIR 和一台风机；第二个 PIR 暂不接入，GPIO3 目前不参与程序。三通及第二条支管是双盆扩展选项。

## 蓝牙控制

设备提供 BLE 控制，并在 v0.5.0 起支持 WiFi STA 配网与 HTTPS 控制。MimiVent App 可通过 BLE 读取状态、配置时序、控制风机、校准时间、读取统计并执行 OTA；WiFi 通道复用同一 `ControlApi` 业务规则，不重新实现控制逻辑。

设备不启动 SoftAP 或内嵌网页控制台；v0.5.0 的 WiFi STA 仅提供 HTTPS API。正式版 v0.3.1 只有 BLE v1 控制通道，不包含 OTA GATT 通道；从 v0.3.1 首次升级到 v0.4.0 必须通过 USB 烧录，完成首刷后可由 App 经 BLE OTA 升级。

## WiFi 配网与控制

- App 经独立的安全 BLE 服务下发 WiFi 凭据；Android 手机搜索网络，设备不执行 WiFi 扫描，避免 BLE/WiFi 共存时内存不足。
- 配网要求 BLE 已加密并 bonding。无屏设备采用系统配对，不执行 MITM 身份认证或自定义六位码验证；在可信设备附近操作。
- 支持 2.4 GHz WPA2-Personal 与 WPA2/WPA3-Personal 混合网络；凭据保存在 NVS，开机恢复连接。App 不保存 WiFi 密码，日志不记录密码或完整配网正文。
- HTTPS `8443` 提供状态、设置、控制、统计、事件与请求结果查询，使用设备证书固定和 Bearer token；不启动 SoftAP、明文 HTTP 或内嵌网页。
- 绑定经安全 BLE 管理，设备最多保存三个有效客户端；支持待绑定、核验、幂等提交、撤销和清除全部绑定。清除绑定同时释放 WiFi 租约，不等于清除 WiFi 密码或全部设备数据。
- 同时只有一份 WiFi 控制租约，空闲 20 秒过期，另一手机需等待释放/过期；BLE 控制与 WiFi 控制通过共享业务层协调。两份绑定不代表两路并行 WiFi 主控。
- HTTPS 单连接、请求有界排队；写请求使用请求 ID 去重和结果查询，超时后先确认执行结果。
- 校时仍经 BLE `/api/time` 完成，HTTPS 不提供该路由；断电重启后无可信时钟时，日期统计需等待校时。
- OTA 仍只走 BLE。升级动态分配工作区，必要时释放 HTTPS 或暂停 WiFi 为 OTA 腾出内存，暂停/结束后恢复网络服务。

## 时序配置

时序设置通过 MimiVent App 经 BLE 调整并保存在 ESP32 NVS 中，无需为更改时序重新编译或烧录。统计自然日时区在设备首次可信校时后固定，后续手机时区变化不会重解释历史日期。首次运行默认值如下：

| 配置项 | 正式运行 `/` | DEV 联调 `/dev` |
| --- | ---: | ---: |
| 启动冷静期 | 30 秒 | 5 秒 |
| 离开确认时间 | 30 秒 | 0 秒 |
| 自动排风时长 | 2 分钟 | 10 秒 |
| 临时排风时长 | 1 分钟 | 10 秒 |
| 临时暂停时长 | 5 分钟 | 10 秒 |

每项都可选择 0、5、10、20、30 秒或 1、2、3、5、10 分钟；只有离开确认时间支持 0。两套配置分别保存，改动后点击“保存设置”。“重置配置”会将当前环境五项时序恢复为表中默认值并立即保存。保存或重置不会重置正在进行的计时，从下一轮或下一次手动操作起使用新值。升级时会把旧固件内置的正式 1 分钟和 DEV 10 秒冷静期默认值迁移到新默认值；其他已自定义时长保留。

设备上电或烧录后重启时，先进入启动冷静期并保持风机关闭，同时监测 PIR 电平但不执行自动排风。冷静期默认正式 30 秒、DEV 5 秒；普通临时排风和临时暂停在冷静期内不可启动。强制排风测试与持续关闭可以跳过冷静期：测试会取消剩余冷静期并按所选时长运行，结束后回到自动感应；持续关闭会取消冷静期并保持关闭，直到手动恢复自动感应。每次重启都默认进入正式配置；DEV 仅在本次开机期间有效。两套时序参数分别保存在 NVS，切换环境后按目标环境的冷静期重新计时。App 所选环境与设备不一致时会锁定控制，直到用户确认切换设备环境或让 App 跟随设备。

PIR 模块自身输出 HIGH 的保持时间由模块电位器控制；软件离开确认时间从模块输出转为 LOW 后才开始计算。因此两者会共同决定猫离开后的实际等待时间。

## 建议的 BLE 联调顺序

1. 第一次验证控制时，让风机 12V 正极保持断开并做好绝缘，给 ESP32、PIR 和继电器控制侧供电。
2. 手机打开 MimiVent App 并通过 BLE 连接设备，检查状态、PIR 状态和模式。
3. 测试短时排风和暂停，确认到期后自动恢复感应；再测试持续关闭的二次确认和恢复自动感应。
4. 断电后再接回风机正极，重新上电并通过 App 验证自动排风和延时停止。

## 固件模块

主程序 `MimiVent.ino` 负责模块初始化和循环调度。`ControlApi` 维护业务规则，`BluetoothManager` 提供 BLE 控制，`WifiProvisioningManager`/`WifiHttpsServer` 提供 WiFi 配网与 HTTPS 控制，`OtaManager` 管理 OTA 任务和分区写入，`StatisticsStore` 管理统计存储；WiFi 传输适配层复用同一业务接口。
